# LANDLINE_ICALL — UDP 3520

## التشغيل
- شغّل Call Integration الحالي: `npm run dev`، ثم `npm run call:icall` في عملية مستقلة.
- يستمع المحوّل على UDP `0.0.0.0:3520` ويقبل المصدر `192.168.0.90` فقط.
- يرسل عبر `scripts/send-call.mjs` إلى `http://127.0.0.1:9005/api/calls` باستخدام رمز Call Integration الحالي. لا تغييرات على WhatsApp.
- يجب توجيه جهاز iCall إلى عنوان جهاز المكتب والمنفذ UDP 3520. التحقق من الجهاز الحقيقي وإعداد شبكته لم يُنفّذا هنا.
- الحالة وطابور الإعادة محفوظان في `.dispatchpro-local/icall/state.json`، أو تحت `DISPATCHPRO_LOCAL_DATA_DIR/icall`. احتفظ بهذا المجلد عند النقل، وشغّل نسخة واحدة من المحوّل.
- عند تعطل HTTP تُعاد المحاولة كل 5 ثوانٍ بنفس eventId والبيانات، بما يشمل إعادة تشغيل المحوّل.

## صيغة الحزم الحالية
- سجل ASCII بطول 62 بايت، أو 83 بايت تشمل ترويسة بطول 21 بايت تبدأ بـ `^^<U>`، حسب التنفيذ الموجود عند استئناف العمل.
- خطوط `01` إلى `04`؛ أحداث الدخول `I/S` تُنشئ المكالمة، و`I/E` تنهي الحالة النشطة المطابقة. أحداث الخروج تُهمل.
- يُؤخذ الهاتف من حقل الهاتف فقط، ولا يُستبدل باسم المتصل.
- منع التكرار يعتمد على الخط ورقم الهاتف ووقت الجهاز بدقة الدقيقة والسنة المحلية. مكالمتان متطابقتان في الدقيقة نفسها دون وصول حدث انتهاء لا يمكن تمييزهما بهذه الصيغة؛ الحزم المتأخرة بعد الانتهاء تحتاج تحققًا على الجهاز الحقيقي.

## نقطة المتابعة 2026-09-25
- اكتمل اختبار المحوّل الموجود وإصلاح اعتماد الحالة في الذاكرة قبل نجاح حفظها: لا يُرسل حدث فشل حفظه، وتبقى إعادة المحاولة ممكنة.
- نجحت 5 اختبارات مخصصة: التحليل، المصدر والتكرار والخطوط، الاستعادة بعد انقطاع الإقرار، فشل التخزين، وUDP 3520 → مرسل Call Integration الحالي → مستقبل HTTP اختباري مع المصادقة.
- الأمر: `node --test --test-isolation=none tests/icall-udp.test.mjs`.
- لم تُعد اختبارات الأجزاء السابقة أو البناء العام. لم يُختبر جهاز iCall الحقيقي أو إنشاء طلب من حزمة جهاز حقيقية. التالي هو هذا الاختبار الميداني فقط ضمن نطاق المحوّل.
