DispatchPro Site Bridge — Local WhatsApp

تشغيل هذا الموقع: START.cmd فقط، باستخدام runtime/node.exe المرفق.
المستقبل الرسمي TCP 5050 يستخدم بروتوكول OfficeCalls الحالي دون تعديل Android.
لا يشغّل Office Calls القديم أو iCall أو بوابة HTTP إضافية، ولا يستخدم عنوان مكتب خارجي.
Reception وAPI المحليان الحاليان يبقيان كما هما؛ لا تُعدّل الشبكة أو جدار الحماية.

كل إعدادات التشغيل في site-config.json، بما فيها هوية الموقع والمكتب واعتماد الحساب
المحلي وعنوان API والمنفذ ومسارات البيانات. هذا الملف يحتوي كلمة مرور؛ لا تنشره.
site-config.example.json مرجع دون أسرار. النسخة الحالية معدّة لهذا الكمبيوتر بالفعل.

TCP JSON UTF-8 ثم newline، ورد OK <eventId> بعد الحفظ الدائم.
نفس eventId = رنين واحد مهما تكرر الإرسال أو أُعيد تشغيل Bridge.
رقم الهاتف ليس مفتاح إزالة التكرار. معرّف جديد للرقم نفسه = طلب جديد فورًا.
OfficeCalls الحالي يولّد المعرّف الجديد عند انتهاء إشعار المكالمة السابقة.
لا تُستخدم حزم UDP القديمة التي تفقد معرّف الرنين.

الطلبات تنتظر على القرص إذا API المحلي غير متاح، ثم تُرسل تلقائيًا عند عودته.
لا يُفتح المستقبِل مرتين من نفس الحزمة. المنفذ المشغول يعطي خطأ واضحًا ولا يُعتبر نجاحًا.

Mirror اختياري ومعطّل افتراضيًا. تفعيله من mirror.enabled وhost وport فقط.
فشله لا يمنع حفظ الحدث أو وصوله إلى DispatchPro.
يُستخدم بحث الزبون والعناوين الحالي في DispatchPro ويظهر المصدر W في Reception.

احتفظ بـ site-config.json وdata عند تحديث الحزمة. سجل التشغيل: logs/local-site.log.
لا يلزم Build أو تثبيت Node إضافي.
