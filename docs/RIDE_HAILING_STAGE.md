# Ride hailing A–G

Extends the existing ASP.NET API, tenant-filtered EF model, PostGIS and mobile/reception clients. No new backend, network change or bridge/channel change.

- Migration: `20260929180422_RideHailingDispatch` applied to the actual local test database `DispatchProTaxi`, after a custom-format backup. Row counts and hashes of existing IDs remained unchanged: 6 tenants, 301 users, 287 drivers, 5 vehicles, 44,957 customers, 59 rides/requests/reception orders. Updated API is active on the same port 9010. Evidence and backup path are in ignored `.dispatchpro-local/hailing-migration-result.json`.
- Reception → **التوزيع التلقائي · متابعة الرحلات** configures tenant policy. Default `MANUAL`; `AUTO_NEAREST` and `HYBRID` enable automatic customer-app requests. Office assignment overrides an automatic offer. Switching a request to manual stops its timeout; its selected driver is preserved.
- GPS: foreground only, low accuracy/power fix every 20 seconds; send after ≥30m movement or 60-second stationary heartbeat. No offline replay. Server validates captured time and accuracy (≤200m), and throttles writes to ≥10 seconds. Requires browser HTTPS/location permission or Android location permission. No background tracking in this phase.
- PostGIS geography distance is measured in meters; candidates are active, available, same tenant, fresh GPS, no active ride/reception order. Persisted offers exclude already-tried drivers for the lifetime of the request. Missing GPS / exhausted candidates remain searching for office intervention or newly eligible drivers.
- Defaults: GPS freshness 120 seconds (configurable 60–600), offer timeout 30 seconds (10–180). Worker ticks every 5 seconds, including after API restart; expired acceptance is rejected immediately. Scheduled customer requests wait until their scheduled time.
- Existing ride statuses remain unchanged. `Assigned` represents an offer; display projection adds `REQUESTED`, `SEARCHING_DRIVER`, `OFFERED`, etc. Customer identity/vehicle/location become visible only after acceptance. Phone is hidden unless policy enables it. Stale location is not returned. ETA is straight-line distance / 25 km/h behind `IArrivalEstimate`.
- Customer map assets are local MapLibre from the existing dependency; OSM tiles load on map opening. Pickup and destination keep textual addresses and coordinates. Driver tracking map updates the same marker; customer updates reuse existing long polling. Reception monitoring refreshes every 15 seconds while expanded.
